# 信息也是食物：为什么有了 AI，海外求职依然存在巨大的信息差 - 欧洲金融职场为例

- 原贴：https://www.1point3acres.com/home/thread/1186353
- 注：这是一篇方法论长文，不是面经。求职只是它的演示场景之一；核心是"上游信息方法论"和"AI 的正确分工"，已归入 focus/ai-value-creation.md。

## 核心论点（一句话）

AI 抹平的只是"下游信息"（已被写成文章、帖子、榜单的东西）的获取成本；真正的差距一直在"上游"——躺在监管机构数据库里、以 CSV/XML/公示形式存在、没人做 SEO 的结构化公开数据。一万个人问 AI 同一个问题，得到一万份几乎相同的二手答案，然后去投同一批岗位。

## 楼主原文（按原文十节整理）

### 一、一个反直觉的开场

按理说 AI 出现之后信息差应该被抹平。但真在海外找过工作的人都知道：信息差不但没消失，反而在某些维度变大了。因为 AI 抹平的是"下游信息"的获取成本——那些已经被写成文章、发成帖子、整理成榜单的东西。可下游的水，本来就是所有人都能喝到的。

### 二、信息是食物，你吃什么就变成什么

信息的摄入和食物的摄入是同构的。长期喂食下游信息，会产生三种典型损伤：

1. **反馈缺失型创伤**：求职中真正伤人的从来不是"被拒绝"，而是"被拒绝而不知道原因"。投 200 份简历收到 3 个回复，得到的是 200 次不确定性。"高投入 + 随机反馈 + 零解释"是制造习得性无助最高效的配方。
2. **个人符号化**：你原本是一个具体的人（会写 Python、做过三年衍生品定价、想去阿姆斯特丹因为姐姐在那儿），进入平台后被压缩成一串标签：3 yrs exp / non-EU / requires sponsorship / Asian / no local experience。最危险的是你开始用系统的语言理解自己。
3. **被算法接管选择权**：你以为你在"搜索"，其实你在"被推荐"。投喂者的目标函数是留存时长，不是你的就业结果。

### 三、真正的解法：去上游取水，别在下游排队

下游：LinkedIn、Indeed、Glassdoor、小红书、微信群、YouTube 攻略、AI 的二手总结。
上游：牌照库、注册库、行政许可公示、政府开放数据。

上游的核心命题一句话：

> 凡是需要许可才能做的事，世界上必然存在一份公开的"谁被允许做这件事"的名单。这份名单由政府维护，免费、结构化、几乎零噪音、且法律上必须准确。

### 四、案例 A：想进欧洲金融业，怎么找特定城市的公司？

上游做法是把问题反过来问：不问"有哪些公司"，问"在欧盟，谁被批准做这件事"。

关键机制 **MiFID II 授权体系**（Directive 2014/65/EU）：欧盟境内任何实体想合法提供投资服务必须取得授权，且授权是逐项勾选的。Annex I 把业务拆成三段：
- Section A｜投资服务与活动（9 项）：接收与传递指令、代客执行、自营交易（dealing on own account）、资产管理、投资建议、包销、代销、经营 MTF、经营 OTF
- Section B｜辅助服务（7 项）：其中 B(2) 是"向投资者提供信贷或贷款以使其完成金融工具交易"——白话就是保证金融资（杠杆）
- Section C｜金融工具清单：期权、期货、掉期、CFD 等衍生品

"能提供金融 + 杠杆 + 期权服务的实体"是一个可精确检索的法律状态：持有 Section A 相关授权 + B(2) + 覆盖 Section C 相应衍生品。没有这些勾选项的公司法律上不可能做这个业务——一条砍掉 90% 噪音。

具体怎么查：
1. **欧盟总入口 ESMA Registers**：https://registers.esma.europa.eu —— "MiFID / UCITS / AIFMD Entities" 页签，实体类型选 MIF – Investment Firms，可按 Home Member State、实体名称、LEI 筛选；提供机器对机器接口和批量下载。总览：https://www.esma.europa.eu/publications-and-data/databases-and-registers
2. **国别监管机构（NCA）**——字段更细：

| 国家 | 监管机构 | 登记册 |
| --- | --- | --- |
| 德国 | BaFin | Unternehmensdatenbank |
| 荷兰 | AFM | Register beleggingsondernemingen |
| 爱尔兰 | Central Bank of Ireland | Registers |
| 法国 | ACPR / AMF | REGAFI |
| 卢森堡 | CSSF | Supervised entities |
| 塞浦路斯 | CySEC | Regulated entities（大量杠杆/CFD 经纪商注册于此） |
| 意大利 | CONSOB | Albo |
| 西班牙 | CNMV | Registros oficiales |
| 英国（脱欧后） | FCA | Financial Services Register |

3. **三维过滤**：地理（注册地址/分支机构所在城市）+ 权限（是否含 A(3) 自营、B(2) 授信、C 段期权与 CFD）+ 状态（是否有效、有无处罚，ESMA 另有 Sanctions Register）。
4. 最终拿到一张表：实体名称 | LEI | 注册城市 | 授权项 (A/B/C) | 主管机构 | 生效日期 | 状态——可能三百家、可能八百家，其中 80% 在 LinkedIn 上一辈子刷不到（不做 employer branding、不发招聘帖、不给猎头付费）。
5. **从实体落地到人**：官网 → /careers（或 /vacatures）→ 没有招聘页就查 LinkedIn 该公司员工列表 → 筛出目标职位同组的人 → 找 hiring manager → 写一封提到具体业务的冷邮件。

### 五、案例 B：在中国找烟店（同一把钥匙，另一把锁）

在中国卖烟必须持有《烟草专卖零售许可证》，无证经营违法——去发证机关的库里查就能拿到接近全集的名单：
- 国家烟草专卖局政务服务许可证查询入口：http://app.gjzwfw.gov.cn/jmopen/webapp/html5/licquery/index.html
- 各省烟草专卖局各自的查询窗口
- 更好用的是地方数据开放平台：以温州市数据开放平台为例，"烟草专卖零售许可证信息"数据集字段：企业名称 | 注册地址 | 经营方式 | 经营范围 | 许可证编号 | 有效期至 | 发证日期 | 发证机关 | 所属地区 | 是否注销 | 行政区划代码

有了"行政区划代码 + 发证日期 + 是否注销"三个字段，能算出的远超"有多少家店"：密度（街道每千人持证数→饱和度）、趋势（按发证日期分组→扩张/收缩）、空白点（注销数 > 新发数→商圈衰退信号）、准入难度（结合"合理布局"间距规定反推新证空间）。

### 六、扩散：把这把钥匙插进别的锁

| 你想知道的 | 上游数据库 |
| --- | --- |
| 一家公司真实的股东、董事、年报 | Companies House（英）/ Handelsregister（德）/ KVK（荷）/ Infogreffe（法）；欧盟 e-Justice 商业登记互联系统 BRIS |
| 谁刚拿到大额政府/公共合同（拿到钱 = 要招人） | TED — Tenders Electronic Daily（欧盟公共采购公告） |
| 哪个实验室刚拿到欧盟科研经费 | CORDIS（Horizon Europe 项目库）、ERC 获资助项目列表 |
| 谁在做临床试验、进度到哪一期 | 欧盟 CTIS、美国 ClinicalTrials.gov |
| 一家公司下一条产品线是什么 | EUIPO 商标库、EPO Espacenet 专利库（商标注册通常早于产品发布 6–18 个月，是最好用的先行指标之一） |
| 美国非上市公司谁刚完成融资 | SEC EDGAR 的 Form D 备案 |
| 谁在扩建办公室/厂房（扩张信号） | 各市政的规划许可（planning permission）公示 |
| 中国：某地新开了多少家药店/餐饮/教培 | 对应许可证公示 + 国家企业信用信息公示系统 + 地方数据开放平台 |

注：原文提到"对海外求职最直接的三个"（疑似指担保资格类名单），并指出：很多沉默不是因为你不行，是因为那家公司法律上就没有担保资格——先用名单把不可能的公司剔除，剩下的投递才有意义。

### 七、一套可复用的五步流程

1. **把名词换成动词**：不问"有哪些量化公司"，问"谁被批准做自营交易"；不问"哪家公司好"，问"谁被批准做这件事"。
2. **找到管这个动词的机关**：金融→证券监管机构；招人→移民局；卖烟→烟草专卖局；卖药→药监；开餐厅→市场监管。这一步 AI 极其好用——它最擅长把白话翻译成官方术语。
3. **找它的公示库**，搜索模板：`site:.gov.uk "register of" [牌照名]` / `site:europa.eu "public register" [牌照名]` / `"行政许可" "公示" [许可证名]` / `open data / 数据开放 [许可证名]`。
4. **三维切片**：地理 + 权限 + 状态。
5. **落地到人**：实体名 → 官网 careers → LinkedIn 员工 → 具体的 hiring manager → 冷邮件里提到他们的具体业务。

### 八、AI 在这个流程里的正确位置

大部分人用错了 AI，把它当成取水的人，其实它是烧水的人。

❌ 错误用法："阿姆斯特丹有哪些量化公司？"→ 二手、过时、可能带幻觉的下游榜单，和所有人一样。
✅ 正确用法：
- "在欧盟提供杠杆交易服务需要哪一类授权？对应法条是哪一条？"（术语翻译——AI 最强的领域）
- "帮我读懂 MiFID II Annex I Section B(2) 的适用范围"（法条解释）
- "这是我下载的 CSV，帮我按城市分组、去掉已注销的、按授权项打标签"（结构化数据处理）
- "根据这家公司的业务描述，帮我写一封提到他们具体产品线的冷邮件"（批量个性化）

> AI 不负责替你取水，AI 负责替你把水烧开。取水这件事，你必须自己走到上游去。

### 九、上游数据的局限（不说这个就是骗人）

- 牌照库告诉你"谁被允许做"，不告诉你"谁在招人"——给的是骨架，不是完整画像，仍需下游信息补肉。
- 持牌实体 ≠ 招人实体：大集团结构复杂，持牌的可能是一个空壳法人，实际团队在另一个国家的另一个实体里。
- 更新频率差异大：英国担保人名单几乎每周更新，荷兰月更，有些国家的库半年不动一次——用之前先看"最后更新日期"。
- 有人拿这个卖钱：网上大量订阅站把 GOV.UK 的免费 CSV 包装成 £9.99/月的"独家数据库"——自己下载 + Excel 筛选，功能完全一样。
- 只覆盖受监管行业：想进一家不需要任何牌照的创业公司，这套方法帮不上忙。

### 十、回到最开始：这为什么是心理健康问题

从"被投喂"切换到"主动取水"，这个动作本身就有治疗性——它改变了你在这场关系里的位置。在下游你是被评估的客体；去到上游，你是做评估的主体：手里有一张四百家公司的表，是你自己筛出来的。同样是花一个下午，投 40 份简历和拉一张 400 家公司的清单，前者产出的是焦虑，后者产出的是地图。

> 信息主权是心理健康的前提。一个人失去对自己信息食谱的控制权之后，情绪就不再属于自己了。

## 要点提炼

- **方法论内核**："许可名单"万能钥匙 + 五步流程（名词转动词 → 找主管机关 → 找公示库 → 三维切片 → 落地到人），可迁移到任何受监管/需许可的领域。
- **AI 分工**：烧水不取水——术语翻译、法条解释、CSV 结构化处理、批量个性化冷邮件；不要让它给你二手榜单。
- **商业信号**：免费公开数据被包装成付费订阅（£9.99/月卖 GOV.UK 免费 CSV）——说明"上游数据 + 处理 + 呈现"本身就是一门生意。
- **局限**：只给骨架不给肉（不告诉你谁在招人）、持牌实体可能是空壳、更新频率不一、只覆盖受监管行业。
